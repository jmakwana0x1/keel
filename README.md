# keel

A Uniswap v4 hook that makes depth a contract. Depth is measured by tick-walk replay, sold to a curator, paid per block it holds, and slashed when it does not.

Status: **Phase 1 (the meter) closed at Gate 1. Phase 2 (mandate, prove, bond) in progress.** Design decisions: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Open measurement questions: [`docs/OPEN-QUESTIONS.md`](docs/OPEN-QUESTIONS.md). Phase 0 economics: [`data/phase0_results.md`](data/phase0_results.md).

Every figure below traces to a committed file in `data/`. Figures marked *machine-checked* are regenerated by a test and diffed in CI; *measured* figures come from a real chain or a fork.

## The meter (Phase 1)

`DepthLib.walk` replays the swap that moves the price to a target, one `SwapMath.computeSwapStep` per step, and reports the pre-fee input.

| Claim | Evidence | Kind |
|---|---|---|
| **Exact** against the real `PoolManager`: zero tolerance, both directions, all four fee tiers, books with voids, both swap shapes | `test/differential/MeterVsPool.t.sol`; coverage asserted (crossings, word-boundary steps, voids all exercised) | machine-checked |
| Exact against the spec-derived Python reference | `test/differential/MeterVsPython.t.sol` → `sim/depth_reference.py` | machine-checked |
| Saturation reproduced in Solidity: all **20,700** Phase 0 walks on **2,070** real mainnet books equal Phase 0 to the unit; class medians 1.105 / 1.039 / 1.000 | `data/phase1_saturation_solidity.csv`, `sim/check_phase1_saturation.py` | machine-checked, on measured books |
| A capped walk never declares a breach. A capped walk whose lower bound clears the target proves compliance | `test/fuzz/DepthBoundary.t.sol`, fuzzed across `MAX_STEPS` | machine-checked |
| Curator contribution in closed form equals **floor** of the exact rational contribution: one rounding, never over-credits | `data/phase1_contribution.json`, D1.2 | machine-checked |

### Step cap and gas

`MAX_STEPS = 128`. Across the 20,700 real walks out to ±10%, the p99 was 96 steps and the max was 97. Hydra's 64 would leave 8.6% of them inconclusive (D1.1). The meter runs in `prove()`, never on the swap path.

| Crossings | Steps | Gas (storage priced **cold**) |
|---:|---:|---:|
| 1 | 2 | 28,740 |
| 3 | 4 | 46,923 |
| 9 | 10 | 101,538 |
| 64 | 65 | 604,712 |
| 127 | 128 | 1,182,806 |
| 127, compliant early exit at 10% | — | 133,464 |

The marginal cost is about **9,100–9,200 gas per crossing** (`data/phase1_gas.json`, machine-checked; coldness guarded by `test/artifacts/GasColdness.t.sol`). For comparison, Hydra's walk cost about 21.4–21.6k per crossing (`hydra/data/counterfactual_gas.json`). The two figures were not measured the same way: Hydra used warm reads at tick spacing 60, and these are cold reads at spacing 1. Cold reads cost more, so the comparison is conservative against KEEL.

### Contribution accuracy

| Estimator | Against the exact real-valued contribution T |
|---|---|
| Closed form, `contribution()` | `= floor(T)` in 400 of 400 cases; error < 1 unit, always down |
| Two-walk difference | Within `(T − steps, T + steps)`. Worst observed **7** units on 119-step walks |
| Proven gap between them | ≤ `MAX_STEPS` = **128** units, below 1e-16 relative at amounts near 1e18 |

### What the verification found

A rounding bug planted inside v4-core's `SqrtPriceMath` was not caught by the meter-vs-`PoolManager` comparison on the side that compares values, because the pool and the meter share the bug. That test did fail, but only through an underflow revert on the deposit side, so the mutation would have been scored as caught for the wrong reason. Only the spec-derived Python reference caught it on the value side. That is why the second reference is a CI gate (D1.8). Full transcript: [`data/verification.md`](data/verification.md).

## Limitations

Stated before anyone has to find them.

- **No measured price for long-tail mandates** (D1.5). Phase 0 could not size a valid simulated band on long-tail books (D0.15). The hook accepts long-tail pools. The reserve there will start from a stated prior, marked as a prior, and be replaced by the pool's own realised cost as mandates complete (D1.6, not yet built).
- **The skim's elasticity is associational, not causal** (D0.5, D0.10). The skim is restored at the configuration that clears break-even under a 75% discount of ε (s = 5%, φ = 10%, D1.4). It is not yet built.
- **Liveness is assumed** (D1.3). A curator who is compliant but never proves inside a staleness window can be slashed for a stretch that was in fact compliant. Proving is cheap on the compliant path, and a window gives N blocks of notice, but nobody proves for you.
- **Pay scales with proving cadence** (D2.2). One compliant proof pays one block, so a curator who wants every block paid proves every block. That suits a cheap-block chain and not mainnet.
- **A slash freezes the curator's principal** (D2.5). The slash itself takes accrued value only. But negative liquidity deltas are allowed only while a mandate is ACTIVE, so a slashed curator's bands stay in the pool permanently. That, not the accrued retainer, is the real penalty.
- **Phase 2 scope cuts** (D2.6): one live mandate per pool, ERC-20 pools only, a fixed retainer rate, and no skim yet.
