### Findings about the port

1. **Only the Python reference detects a rounding defect inside v4-core.** The rounding mutations sit in `SqrtPriceMath`, which the PoolManager shares. On the side where the PoolManager differential is a pure value comparison (amount1: up walks; amount0: down walks), the mutated pool and the mutated meter agree, and the test **keeps passing**. The Python reference shares no code with v4-core and fails on exactly that side, matching its Phase 0 twin's direction. This is the case for two references in one line.
2. **The PoolManager differential's failures under those mutations are collateral, not detection.** It fails on the *opposite* side by **reverting**: the same rounding governs liquidity deposits, so the pool takes too little of one token, and paying that token out underflows the ERC-20 balance (`Panic(0x11)` inside `transfer`). Reproduced in isolation with `testFuzz_meterMatchesPool_down` under `amount1 rounds down`. A suite that only had the PoolManager reference would have reported this mutation as caught, for the wrong reason (rule 6).
3. **The word-boundary mutation is seen by both differentials in both directions**, because it sits in our adapter, not in shared code. `SaturationReproductionTest` correctly keeps passing: it reads books through `BookTickSource`, not the mutated `V4TickSource`. The Python twin localised to boundary walks only; the Solidity suites are per-direction, not per-walk, so they cannot show that finer localisation.
4. **Suites that keep passing under every mutation** (`DepthBoundary`, `Contribution`, the unit tests, `allTiers_withGap`) test properties that are invariant to these defects. `cappedWalk*` and the verdict table test decisions, not amounts. `Contribution` compares two walks that share the mutated math. For `allTiers_withGap` under the boundary mutation the reason is structural: its word boundaries fall only inside its voids, where liquidity is zero and splitting a step changes nothing. Under the rounding mutations the reason is **not established**; the likely one is that its walks never drain a side of the pool, so finding 2's deposit shortfall never surfaces. None of these suites is the line of defence for these defects, and none claims to be.
